## 1. Что такое **UUID**?

**UUID (Universally Unique Identifier)** - 128-битный универсальный уникальный идентификатор.

---

## 2. Архитектура

Проблема - хранение списка Account внутри сущности User.

Пользователь может иметь много счетов.
Для каждой транзакции доставать каждый из них не оптимально.

Так что я вынес Account в отдельную сущность и для нее своя табличка.
Теперь транзакция ссылается на Account, а Account ссылается на User.

## 3. SOLID

| Принцип | Расшифровка                         | Применение в проекте                                                                                                                                                                         |
|:--------|:------------------------------------|:---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| **S**   | **Single Responsibility Principle** | Каждый класс выполняет одну задачу: `TransactionService` (транзакции), `AccountService` (счета), `Repository` (работа с БД).                                                                 |
| **O**   | **Open/Closed Principle**           | Использование `TransactionStrategy` позволяет добавлять новые типы транзакций (например, новую стратегию) **без изменения** существующего кода.                                              |
| **L**   | **Liskov Substitution Principle**   | Конкретные стратегии (`DepositStrategy`, `WithdrawStrategy`, `FreezeStrategy`) могут быть использованы везде, где ожидается базовый `TransactionStrategy`, **без нарушения** логики системы. |
| **I**   | **Interface Segregation Principle** | Вместо одного большого интерфейса используются раздельные и узконаправленные: `TransactionObserver`, `TransactionStrategy`.                                                                  |
| **D**   | **Dependency Inversion Principle**  | Сервисы работают с интерфейсами репозиториев (`UserRepository`), а не с их конкретными реализациями (`JdbcUserRepository`).                                                                  |

## 4. Паттерны проектирования

1. **Strategy** (`TransactionStrategy`, `DepositStrategy`, `WithdrawStrategy`)
2. **Factory** (`TransactionStrategyFactory`)
3. **Observer** (`TransactionObserver`)
4. **Singleton** (`Database`)

## 5. Асинхронность и атомарность

| Тулза                   | Зачем                                                                                               |
|:------------------------|:----------------------------------------------------------------------------------------------------|
| **`ConcurrentHashMap`** | Используется для эффективного хранения и управления активными блокировками счетов.                  |
| **`ReentrantLock`**     | Используется для блокировки счетов во время активной транзакции, предотвращая одновременный доступ. |
| **`synchronized`**      | Доступен, но менее контролируем, чем `ReentrantLock`.                                               |

По поводу паттернов можно использовать

* **Producer-Consumer** Посредством очереди задач и тредпула. AsyncTransactionProcessor - consumer, client - producer.
* **Command** Каждая транзакция инкапсулирована как объект-команда. Команды можно ставить в очередь, выполнять
  асинхронно и повторно использовать.
