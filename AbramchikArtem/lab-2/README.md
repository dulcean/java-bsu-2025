# Банковский транзакционный процессор (мини-аналог Spring @Transactional)

Проект демонстрирует:
- Базовую работу с пользователем и его счетами
- Систему транзакций
- SOLID
- Паттерны
- Асинхронный обработчик транзакций
- JDBC-слой

---

# 1. Что такое UUID?
UUID (Universally Unique Identifier) — 128-битный уникальный идентификатор, вероятность коллизии которого крайне мала. Используется для уникальной идентификации сущностей (пользователь, транзакция).

---

# 2. Ответ на вопрос об архитектуре
Предложенная структура транзакций (UUID, timestamp, amount, account, action) — нормальная и отражает базовую банковскую сущность.

Но есть улучшения:

- Разделить типы транзакций на стратегии (паттерн Strategy)
- Сделать фабрику для выбора типа транзакции
- Вынести выполнение транзакции в TransactionService
- Добавить статусы транзакций (SUCCESS, FAILED, PENDING)
- Добавить TransactionValidator
- Изолировать логику хранения (DAO слой)

---

# 3. Примеры SOLID

### S — Single Responsibility
- `Account` хранит только данные счёта
- `TransactionService` только выполняет транзакции
- `TransactionRepository` только сохраняет транзакции

### O — Open/Closed
Добавление новых типов транзакций без изменения основного сервиса = стратегии.

### L — Liskov Substitution
Любая стратегия (`DepositStrategy`, `WithdrawStrategy`, `FreezeStrategy`) взаимозаменяема, т.к. реализует один интерфейс.

### I — Interface Segregation
Разные интерфейсы:
- `Freezable`
- `Transferable`
- `TransactionStrategy`

### D — Dependency Inversion
Сервис зависит от абстракций (`TransactionRepository`, `AccountRepository`), а не от конкретных JDBC-классов.

# 4. Паттерны проектирования в проекте

| Паттерн | Где используется |
|--------|------------------|
| Стратегия | Выполнение разных типов транзакций |
| Фабрика | Создание нужной стратегии по типу действия |
| Команда | Транзакция — объект-команда с execute() |
| Наблюдатель | Любое изменение счёта уведомляет слушателей |
| Визитор | Аналитика по счету |
| Синглтон | TransactionDispatcher (пул потоков) |

---

# 5. Асинхронность (и какие механизмы Java используются)

### Что используется:
- ExecutorService — создание пула потоков
- CompletableFuture — асинхронные операции
- ReentrantLock — атомарность изменения счетов
- ConcurrentHashMap — потокобезопасное хранение
- synchronized / lock — защита от гонок данных
- Singleton — пул потоков один на всю систему

---

# 6. Запуск
Просто запустить Main — создадутся пользователи, счета, выполнятся асинхронные транзакции и выведутся логи.
